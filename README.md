# 3장 홀덤 딜러 트레이너

3명의 쇼다운 승자를 판정하는 한국어 교육용 웹앱입니다. 외부 패키지, 계정, API 키 없이 로컬에서 실행합니다.

- GitHub Pages 배포 예정 주소 (배포 후 사용): [3장 홀덤 딜러 트레이너](https://hyun-t1.github.io/3holdem/)
- 소스 코드 저장소 예정 주소 (생성 후 사용): [hyun-t1/3holdem](https://github.com/hyun-t1/3holdem)

현재 로컬에는 자동 배포 구성이 준비되어 있습니다. 저장소 생성과 첫 배포가 완료된 뒤에는 [Actions](https://github.com/hyun-t1/3holdem/actions)에서 배포 결과를 확인할 수 있습니다.

## 실행

Node.js 24 이상이 필요합니다. 프로젝트 폴더에서 다음 명령을 실행하고 브라우저에서 **http://127.0.0.1:4173** 을 엽니다. `npm install`은 필요하지 않습니다.

```powershell
npm start
```

Windows에서는 `start.bat`을 더블 클릭해도 됩니다. 종료하려면 서버 터미널에서 `Ctrl+C`를 누릅니다. 포트를 변경하려면 `npm start -- --port 4174`를 사용합니다.

## 사용 방법

1. 일반 / 어려움 / 전문가 난이도를 선택합니다.
2. 플레이어 한 명, 두 명의 공동 승리, 세 명의 공동 승리 중 정답을 선택합니다.
3. **정답 확인**을 누르면 모든 카드와 실제 승자, 최종 5장, 사용 카드 수 및 상세 비교를 확인할 수 있습니다.
4. **새 핸드**를 누르면 선택과 공개 상태를 초기화하고 새로운 문제를 만듭니다.

요청한 공개 방식에 따라, 답을 제출하기 전에는 홀카드 9장과 커뮤니티 카드 5장이 모두 뒷면으로 표시됩니다. 정답률, 총 판정 수, 연속 정답 및 이전 결과는 브라우저의 `localStorage`에 저장됩니다. 브라우저 데이터를 삭제하거나 다른 브라우저를 사용하면 별도 기록으로 시작합니다.

## 판정 규칙

- 표준 52장 덱을 사용하며 한 문제 안에서 카드는 중복되지 않습니다.
- 각 플레이어는 홀카드 3장 중 **0장, 1장 또는 2장**만 사용할 수 있습니다. 홀카드 3장을 모두 사용하는 조합은 생성하지 않습니다.
- 홀카드 0장 + 공용 5장, 홀카드 1장 + 공용 4장, 홀카드 2장 + 공용 3장의 모든 조합을 평가해 가장 강한 **정확히 5장**을 선택합니다.
- 족보와 모든 킥커를 순서대로 비교하며 무늬에 우열은 없습니다. A-2-3-4-5는 5가 가장 높은 가장 낮은 스트레이트입니다.
- 완전한 비교값이 같으면 공동 승리입니다. 같은 강도의 최종 조합이 여럿이면 홀카드를 적게 사용하는 조합을 대표로 표시합니다.
- 난이도는 출제할 카드 배분 조건만 변경하며 판정 규칙을 변경하지 않습니다.

## 난이도 설계

- **일반:** 족보의 종류 차이로 승부가 나는 기본 판정 문제입니다.
- **어려움:** 같은 페어의 킥커, 투페어 비교 순서, 낮은 A 스트레이트, 홀카드 3장 사용 함정 등 직관적으로 헷갈리는 문제입니다.
- **전문가:** 플러시의 네 번째·다섯 번째 숫자, 풀하우스 비교, 보드에 의해 상쇄되는 홀카드, 사용하지 않는 여섯 번째 카드, 2명·3명 공동 승리 등을 집중 출제합니다. 단순히 강한 족보가 나오기만 하는 문제는 낮은 비중으로 배치합니다.

난이도에 맞는 문제 조건을 먼저 정한 뒤 카드의 무늬, 좌석, 배치 순서 등을 무작위로 바꿉니다. 일부 전문 문제는 숫자도 변형하며, 변형 후에도 족보 종류·승자·홀카드 사용 수가 같은지 평가 엔진으로 재검증합니다. 어려움에는 완전히 섞은 덱에서 같은 족보끼리 경쟁하는 문제를 골라내는 방식도 사용합니다.

## 테스트 및 정적 빌드

```powershell
npm test
npm run build
npm run preview
```

자동 테스트는 10종 족보, 킥커와 휠 스트레이트, 공동 승리, 덱 중복, 홀카드 사용 0/1/2장 및 3장 사용 금지를 검증합니다. `dist/`에 빌드된 결과는 일반 정적 웹 호스팅에도 사용할 수 있습니다. 개발 중에는 `npm run dev`로 동일한 로컬 서버를 실행합니다.

## GitHub Pages 자동 배포

저장소를 생성하고 GitHub Pages를 활성화한 뒤 `main` 브랜치에 변경 사항을 푸시하면 `.github/workflows/deploy.yml`이 Node.js 24에서 자동 테스트와 정적 빌드를 실행합니다. 두 단계가 성공한 경우 `dist/` 결과물만 GitHub Pages에 배포합니다. 테스트가 실패한 변경 사항은 배포하지 않습니다.

저장소 설정의 **Settings → Pages → Build and deployment → Source**는 **GitHub Actions**를 사용합니다. 필요하면 Actions의 **Test and deploy GitHub Pages → Run workflow**에서 수동으로 다시 배포할 수 있습니다. 별도 서버나 API 키를 설정할 필요가 없습니다.

## 구성

- `index.html`, `styles.css`: 반응형 카지노 테이블 화면
- `src/app.js`: 문제 진행, 결과 표시 및 브라우저 기록
- `src/poker.js`: 5장 족보 평가와 제한된 최적 조합 계산
- `src/deals.js`: 난이도별 무작위 문제 생성
- `tests/`: Node.js 내장 테스트 러너 자동 검증
- `scripts/server.mjs`: 의존성 없는 로컬 HTTP 서버
- `scripts/build.mjs`: 배포용 정적 파일 생성
- `.github/workflows/deploy.yml`: 테스트 성공 후 GitHub Pages 자동 배포
